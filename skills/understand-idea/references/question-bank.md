# Question bank

Grounded questions for the four gaps in the `idea` block: goal, who benefits, success and
constraints. Ask only about a gap the first message and the documents left open, one at a time
(CON-2). Each question carries a recommendation and two or three short choices, with the
recommended one marked (CON-1, TALK-8). Adapt the wording to the user's own words and the project's
documents; never read the list out.

## Goal (who gets what value)

Ask when the message gives only an activity ("add an export button") and not the value behind it.

- "What should this make better for people, and for whom?"
- Offer choices drawn from the documents, for example: save them a support call (recommended),
  let them self-serve, or cut a manual step for the team.

## Who benefits

Ask when the people served are unclear.

- "Who is this mainly for?"
- Offer the roles the project documents actually name, for example: existing customers (recommended
  if the idea is customer-facing), the support team, or internal admins.

## Success (what good looks like)

Ask when there is no measure. If the user cannot say, switch to `references/success-prompts.md`.

- "How will we know this worked?"
- Offer two or three suggested measures, each labelled a suggestion, for example: fewer support
  calls about this, more people completing it themselves, or less time spent per case.

## Constraints

Ask when limits are unclear.

- "Is there anything this has to respect: a deadline, a cost ceiling, a rule, or a system it must
  fit?"
- Offer the common ones for the project, for example: must not change billing, must work for
  existing customers, or must ship before a known date.

## Using "I don't know"

Always accepted. Offer the recommended choice as a default, say plainly it is an assumption, and
note it so it can be recorded in the assumptions block. Move on; do not press.
