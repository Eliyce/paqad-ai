# Publication budget

The published `index.md` sits in the always-loaded tier, where attention is a budget. A bloated
index gets ignored, so the index is capped and the prose must earn every token. This reference is
the budget discipline.

## What is generated vs curated

- **Generated by the engine (do not hand-edit):** the `index.md` skeleton, the `overview.md`
  Mermaid flowchart, and the screen/API registries. These are deterministic projections of the
  map; editing them by hand desynchronises the map from its views.
- **Curated by this skill:** the short narrative inside the index and a one-sentence framing per
  area around the overview. Prose only.

## Staying inside the budget

- The index has a token cap. When the full map does not fit, the engine drops optional tiers in a
  defined order and records the omission. Keep the narrative short enough that it never pushes the
  index over the cap.
- Every dropped tier gets an explicit omission note. A trimmed index that reads as complete is a
  quiet lie; the note is what keeps it honest.

## Prose discipline

- Say what the diagram cannot: what the app is for, where a newcomer starts, which areas matter.
  Do not restate the nodes and edges in sentences.
- Never narrate a surface or journey the map does not contain. The prose describes the map, it
  does not extend it.
